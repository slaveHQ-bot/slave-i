# Engineering Planner

Convert product goals into implementation-ready engineering work.

## Process

Requirement
→ clarify objective
→ identify affected systems
→ 
→ identify dependencies
→ define acceptance criteria
→ split tasks
→ identify parallelizable tasks
→ identify risks
→ produce execution plan

## Good task

A good task has:
- one clear owner
- clear boundaries
- measurable acceptance criteria
- known dependencies
- expected output

## Avoid

"Improve memory."

Instead:

"Add project-memory persistence with schema, repository API, validation, retrieval query, migration, unit tests, and integration tests."

## Parallelization

Explicitly label:
- can_run_parallel
- dependency
- file_conflict_risk

## Output

Return a task graph, not a vague checklist.
